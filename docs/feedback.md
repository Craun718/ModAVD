# 反馈问题

在本仓库的 Issues 里提。提之前先搜一下有没有人报过同样的问题。

## 1. 收集问题信息

1. **出问题后先别关模拟器。** 实例还开着的话，收集时会顺带记下当时的画面和状态。
2. 双击文件夹里的「收集问题信息.bat」。大约一分钟，桌面上会生成 `魔改AVD问题信息-<时间>.zip`，并自动在资源管理器里选中它。

这个脚本只读不写：不关机、不重启，不上传任何东西。它收集：

| 内容 | 说明 |
|---|---|
| `summary.txt` | 模拟器、adb、系统镜像的版本，文件夹路径和所在盘的剩余空间，Windows、CPU、内存、显卡型号和驱动版本，虚拟化相关 Windows 功能的状态，`emulator -accel-check` 的结果，杀毒软件名称，正在运行的模拟器进程和命令行 |
| `avd\` | 每台实例的配置文件（`config.ini` 等）和实例文件夹里的文件名、大小清单 |
| `logs\` | 模拟器日志和安卓日志（logcat），每台实例各取最新 8 份；「补全组件」的日志 |
| `crash\` | 近 7 天的模拟器崩溃转储，最多 3 份 |
| `mas\` | AUTO-MAS 的 `debug` 文件夹里的日志 |
| `live\` | 正在运行的实例：一张截图、系统属性（getprop）、当前窗口、安卓崩溃日志 |

它**不会**拿：实例的磁盘镜像（游戏数据都在里面），AUTO-MAS 的 `config` 和 `data` 文件夹（里面有加密过的账号密码）。

## 2. 哪些公开贴，哪些私下发

**Issues 是公开的，附件谁都能下载。** 上传前请打开 zip 看一遍。

| 内容 | 怎么给 |
|---|---|
| `summary.txt`、`avd\`、`logs\`、`mas-avd.json` | 可以贴到公开 Issue。里面的路径可能带 Windows 用户名，介意就先改掉 |
| `live\`（截图、系统属性、当前窗口、安卓崩溃日志）、`mas\`（AUTO-MAS 日志） | 可以贴，但先看一眼：截图可能拍到游戏昵称、账号信息，AUTO-MAS 日志里可能有你在 AUTO-MAS 里填的用户名。不想公开的删掉或打码，或者改为私下发 |
| `crash\`（崩溃转储） | **不要公开上传。** 它含有模拟器进程的线程栈、少量内存片段和本机路径（路径里有 Windows 用户名），不含安卓系统的完整内存，也不会有意收集账号密码 |

做法：

1. 在 Issue 里贴不含 `crash\` 的部分（把 `crash` 文件夹从 zip 里删掉再上传，或者只贴 `summary.txt` 的内容），并写明「有崩溃转储，已发邮件」。
2. 把**完整的问题包**（含 `crash\`）发邮件到 **qiyinxi@foxmail.com**，标题或正文里写上 Issue 编号。附件太大发不出去时，在 Issue 里说一声。

## 3. 写清楚

- 大概什么时间，在做什么任务（哪个脚本、哪个游戏）；
- 看到了什么，有截图就附上；
- 能不能重现，怎么重现；
- 模拟器版本（`sdk\emulator\source.properties` 里的 `Pkg.BuildId`）和 AUTO-MAS 版本。问题包的 `summary.txt` 里已经有这两项。

「补全组件.bat」出错时，附上 `logs\fetch-components.log` 就够了。它只记录下载过程（用了哪个镜像、哪个地址、在哪一步出错）和文件夹路径。
